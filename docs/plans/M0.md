# M0 Foundations: plan

**Done when:** CI is green; an architecture test fails if one module reads another's tables; a new machine runs the app with one command.

## Repo layout

- `app/Modules/<Name>/`: the 11 modules (Identity, Creators, Content, Media, Wallet, Subscriptions, Messaging, TrustSafety, Notifications, Audit, Collaborations). Each has `Actions, Contracts, Database/Migrations, Events, Gateways, Http, Jobs, Models, Policies, Providers, Tests` and a `README.md`.
- `app/Modules/<Name>/Providers/<Name>ServiceProvider.php` extends `App\Support\Modules\ModuleServiceProvider`. It declares the tables the module owns (`TABLES`), loads the module's migrations and binds its gateway contracts.
- `app/Support/`: the shared kernel modules may use (Money, webhook signatures, module and driver plumbing). It must never use `App\Modules`.
- `config/fanfolio.php`: every business constant and gateway driver choice. `env()` is read only in `config/`.
- `docs/`: sources of truth, `decisions.md` and plans.
- `docker/`, `compose.yaml`, `Dockerfile`: local runtime.
- `infra/terraform/`: infrastructure skeleton; the region is a required variable.
- `.github/workflows/ci.yml`: CI gates.

## Architecture tests (fail the build)

1. A module may reference another module only through `App\Modules\<Other>\Contracts\*` and `App\Modules\<Other>\Events\*`.
2. A module's code may not name another module's table in a string literal (`DB::table`, `$table`, joins, raw SQL).
3. A module's migrations may only create, alter or drop tables it owns. Every owned table belongs to exactly one module.
4. Module migrations use ULIDs: no `id()`, `increments()`, `bigIncrements()` or `foreignId()`.
5. No floats in modules or the shared kernel: no `float` types, `(float)` casts, `floatval()`, float or decimal casts, or float, double or decimal columns.
6. `env()` appears only under `config/`.
7. Strict types everywhere in `app/`; no `dd`, `dump`, `var_dump` or `ray`.
8. Domain events implement `ShouldDispatchAfterCommit`.
9. `App\Support` never uses `App\Modules`.
10. Every module has a README and a provider registered in `bootstrap/providers.php`.

The scanner behind rules 1–5 has its own tests with bad fixture code, which proves each rule catches a violation.

## Gateway interfaces and Fake drivers

| Contract | Module | Fake behaviour |
|---|---|---|
| `TopUpGateway` | Wallet | Hosted-checkout URL on the app; webhook events signed with HMAC, timestamped and replay-protected |
| `PayoutGateways` → `PayoutGateway` per rail (bank, usdt, paxum) | Wallet | Records instructions; outcome scriptable (sent, pending, failed) |
| `FxRateProvider` | Wallet | Fixed integer rates (micro-units), never floats |
| `IdentityVerifier` | Identity | Scriptable pass, fail or review results; DOB and age-over-18 result; on-demand document image (D-01) |
| `SmsSender` | Identity | Records messages in memory and logs |
| `DrmLicenseService` | Media | Clear-key in local and testing only |
| `MalwareScanner`, `AbuseHashMatcher`, `ContentClassifier` | Media | Clean by default; scriptable matches |
| `LeakCrawler` | TrustSafety | Returns scripted sightings |

A Fake driver refuses to boot in `production`. An unknown driver name fails at resolve time.

## Runtime

`docker compose up` runs everything:
- `app`: Octane on Swoole, port 8000
- `horizon`
- `scheduler`
- `postgres` 17
- `redis` 7
- `meilisearch`
- `minio`: S3-compatible stand-in for R2
- `mailpit`

On first start, the entrypoint installs dependencies, creates `.env`, generates the key and runs migrations.
